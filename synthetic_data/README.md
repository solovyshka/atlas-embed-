# Синтетические данные

Генератор создает `applications.csv` со столбцами:

- `app_id` — последовательный идентификатор заявки;
- `client_id` — случайный идентификатор клиента, клиенты могут повторяться;
- `reg_region_code`, `fact_region_code` — модельные коды регионов `0..69`;
- `equal_flag` — `1` только для совпадающих регионов, но у 10% совпадений остается `0`;
- `flag_6m_30p` — ровно 2% положительных значений для 1 млн строк;
- `score_dubai` — модельный скор с ROC AUC `0.75` по `flag_6m_30p`;
- `issue_dt` — случайная дата от `2024-01-01` до `2026-08-31` включительно.

Таргет генерируется с устойчивым риском по регионам и `equal_flag`, поэтому
региональная residual-модель может добавить сигнал поверх `score_dubai`.
Сила эффекта регулируется параметром `--region-risk-strength`.

Запуск из корня проекта:

```bash
.venv/bin/python synthetic_data/generate.py
```

По умолчанию создается 1 млн строк с фиксированным `seed=42`. Размер,
диапазон дат, число регионов, вероятности и целевой ROC AUC можно изменить
через `--help`.

## ОКВЭД поверх готового скора

`generate_okved.py` создает отдельный датасет для сравнения flat и
иерархических ОКВЭД-эмбеддингов:

- `primary_okved` — основной ОКВЭД переменной глубины, например `69.10` или
  `46.74.2`;
- `boost_score` — готовая вероятность базовой модели;
- `target` — бинарный таргет, сгенерированный после `boost_score` как
  `sigmoid(logit(boost_score) + okved_delta)`;
- `client_id`, `issue_dt` — идентификатор клиента и дата заявки.

Режимы сигнала:

- `no_signal` — ОКВЭД не влияет на таргет;
- `flat` — эффект задан на полном коде;
- `hierarchical` — эффект разделяется между уровнями `L1` и `L2`;
- `mixed` — одновременно иерархический и leaf-эффект.

Пример запуска с кодами, впервые появляющимися после train-периода:

```bash
.venv/bin/python synthetic_data/generate_okved.py \
  --rows 20000 \
  --regime mixed \
  --oov-rate 0.04 \
  --oov-cutoff 2026-01-01
```

Безопасный формат агрегированных статистик для настройки генератора приведен
в `okved_stats.example.json`. Он содержит только агрегаты; клиентские и
заявочные строки передавать не требуется. Поле `expected_bads` — сумма
готового `boost_score` внутри агрегата; вместе с `count` и `bads` оно задает
сглаженную residual-поправку ОКВЭД поверх базового скора.
